# PEX research protocol1 contract (frozen before implementation)

Scope: one paused full16380-word16MS/s capture of known synthetic2Mbps16-byte RFTX; original exact DFA. Default-off ESP32-only build option. Ordinary commands byte-identical unless explicitly busy under an active PEX retention lease. No generic/Quest/continuous claims. Source pins in BASE-PINS.json; v9 modified archive base, not clean current main.

PEX? reports protocol, support and retained generation. PEX <cap0..64> requests exactly one capture. PEXGET <generation> exports full65520-byte immutable input, not BANKGET's8188-word data. PEXDROP <generation> releases. Strict unsigned decimal, exact count; boot-local monotonically increasing uint64 generation refuses wrap. Boot token generated once in unmapped command context binds generation; not cryptographic authentication. No silent cross-capture joins/dedup.

Transport: text header `PEXFRAME 1 KIND BOOT GENERATION META_BYTES PAYLOAD_BYTES CRC32\n`, followed by exact metadata and payload binary, followed by bounded `\nPEXEND 1 KIND BOOT GENERATION\n`. KIND1 result, KIND2 IQ. Metadata is64 little-endian uint64 fields (512bytes), zero reserved; payload result1844bytes or input65520bytes. CRC32 is ESP ROM crc32_le with seed0 over metadata then payload. Protocol, kind, boot and generation are duplicated inside CRC-covered metadata. Result layout is frozen original1844-byte pkt_result with assertions; metadata indexes enumerated in implementation header. Header/trailer generation/count/version equality required by host. No success on failed/truncated send. Source packet airCRC is distinct from this transport CRC and input CRC.

Metadata includes explicit stage timestamps and per-stage heap/stack snapshots, actual/requested words, input/result CRC, cap, settings, pre/post152-byte DC fingerprints (CRC32, not calibration epoch), baseline freshness and status. Full DC bytes additionally stored with candidate evidence if exposed by future protocol; CRC fingerprint collision/changes-and-reversions are not excluded. Firmware outputs are not host IQ proof until GET verified. Result emission timestamps not knowable in its preceding payload: separate PEXCOST terminal reports post-output/drain time; command/GET/DROP host durations logged independently. Missing terminal means incomplete, never implicit success.

State: idle -> admission+allocate -> prepare/clear/filter -> lease/map/trigger/poll/restore -> unlock/filterrestore -> validate/copy -> decode -> output -> retained. No allocation, UART, scheduler, callbacks or full-copy while mapped. Keepinterrupts/WDT/coreaffinity.20ms hardware wait; decoder100ms post-return reject (not preemption),5s capture-work beforeoutput limit. STOP at safe boundaries, pending STOP during capture handled only after restoration. Timeout/invalid memory/staleDC/STOP invalidates generation and frees all private memory exactlyonce. Status errors include generation where assigned; no success result.

Lease is bounded to one private buffer+context; it survives host disconnect and RELEASE because existing serial service has no disconnect callback. Valid until explicit DROP or60s since successful capture, lazily expired at next application command. Not background timedfree. Any non-PEX command before expiry gets busy without sideeffects; after expiry resources released before ordinary dispatch. PEXGET does not renew expiry. Read-only recovery PEX? and explicit DROP available after client reconnect. GET transportfailure frees lease. Owner identity is serialport, not host authentication.

Calibration: initially ready/fresh required; no implicit calibration. Unlocked PBUS/gain/LO prep and filter_apply, then single nonblocking try-acquire existing initialized PHY mutex, verify live DC freshness/copy fingerprints; direct register capture only; restore owner/ADC/byte-select then snapshot/unlock, then filter_restore. No ROM I2C/PBUS under lease. All controlled honoring writers excluded; vendor/autonomous/modeminterrupt activity not universally frozen. No monotonic calibrationepoch claimed. Lock/task/context addresses must be internal/nonaperture; original linker reservation preserved. See LOCK-PREFLIGHT.md.

Admission rejects scheduled/armed operation, existing bank/detector retention, active dump, nonUART, unsupportedfrequency outside2400..2500MHz, missingcalibration, badpointers, insufficientallocation/stack. Runtime free/largest-block snapshots are not proof of continuous peakheap; static address checks not full task stack bound. No hardware resource admission claimed from build.

Before release to hardware: independent source/cleanup review, host mock failures/STOP/cap/negative transport, default-off build plus pinned opt-inbuild, source/hash manifests. Hardware later requires supported permission, awake recovery and per-board verifiedv9restoration. No firmware success or RF recall from native mocks.
