# Layered timeout candidate: receipt schema 3

Separate offline implementation of HALF_WAIT_QUARTER_SETUP_V1. Frozen bounded adapter v2 and the collector/native/fixture sources remain unchanged. The collector API still means whole-call timeout; its total/frame/read/write/quiet/silence/ownership checks have not been relaxed.

## Exact source contract

The operation clock starts after acquiring the owner lock and checking local availability, before timeout argument conversion, bounded admission, maximum-record encoding, or backend getters. Source constants use B integer nanoseconds, I=B//2, A=B//4, F=(7*B)//8. Positive B<8 ns rejects before backend access. Quiet has metadata requested timeout zero, effective B=10,000,000 ns and I=0. The assigned wait is nextafter(I/1e9,0) or exactly zero. No dynamic recomputation, retry or grace widening.

Pre-I/O checks occur after admission but before settings access, before the single timeout setter, and immediately before read/write. They require nonnegative elapsed < A and B-elapsed >= I+(F-A-I)+(B-F). Closed additional errors: 18 SETUP_HEADROOM (including unrepresentably small positive request), 19 RETURN_HEADROOM (F exceeded but B not exceeded), 20 CLOCK_BACKWARD. Actual observed B overrun retains code 10 DEADLINE and has precedence over either headroom classification. Existing codes 1–17 remain unchanged. Missing/invalid clock is distinct from a known late timestamp. Restoration error stays secondary if a later time observation also fails.

After restoration, a first final observation checks elapsed, then a bounded record is encoded. A second observation includes that initial encoding cost, checks deadlines and poison, updates metadata elapsed, and makes final return eligibility explicit. The final record encoding, append, lock release and return are after the last observation, covered only by reserved headroom and the collector's independent whole-call measurement. Metadata position 7 therefore means last observed elapsed checkpoint, NOT actual total call duration. The collector's clock starts earlier than the adapter clock; entry work also consumes the available reserve. No universal scheduler/backend/property-getter timing guarantee exists. An arbitrarily late stall may be detected only by the collector, which must invalidate trust and issue no subsequent cleanup command.

Operation format stays 24 scalars. Export schema is explicitly 3, with fixed timeout_policy string HALF_WAIT_QUARTER_SETUP_V1. Requested-timeout metadata plus pinned source reconstructs the configured inner wait; old schema-2 evidence/validators must not silently accept or reinterpret schema 3. The bounded 4,096-byte receipt limit is still checked. No schema-2 validator was changed. The 160 MiB audit-content bound is not an RSS bound; no large preallocation or load test.

## Tests and disclosed preparation failure

All 31 tiny fake tests passed: 21 prior bounded-adapter regressions and 10 layered groups. The first inherited test run had one test-fixture error: an old finite clock iterator exhausted after the new additional observations. Its log is preserved (inherited-initial.log), as is the exact old test under baseline. That test now changes to a constant late clock after backend return, exercising the same known-overrun assertion without depending on a fixed number of clock calls. No fraction, threshold or policy was tuned.

Exactly three matching corrected cases were then executed once via corrected_cases.py, which refuses an existing result file. Full-inner-wait empty and partial reads finish at synthetic 52 ms (approximately 50 ms assigned backend wait plus 1 ms setup and 1 ms restoration) and pass actual Collector.read. Early 10 ms empty finishes at 12 ms. Partial bytes are delivered and logged once; empty returns do not reset collector progress. Original v2 tests rejected the first two at 102 ms and accepted the early case at 12 ms; originals are preserved, not overwritten. These costs are specified fake inputs, not pySerial measurements.

The partial-read harness initializes actual collector transcript/log fields and calls Collector.read/quiet/remaining, but bypasses its constructor/native verification. This is not a full session or new IQ/decoder test. No full synthetic transcript was run for this candidate. Tests also cover insufficient setup headroom before I/O, actual outer overruns, conservative F exhaustion/equality, negative clock, late encoding, quiet unexpected bytes/overrun, partial writes, finite silence cutoff and schema-3 receipt bounds.

Still requires independent source/tiny-test review. No hardware, serial import/open, real sleep, new IQ, stress, firmware/default change, installation or publication. Live use remains on hold until separately authorized backend/recovery qualification. Reduced write waiting is an explicit compatibility tradeoff, not evidence that all real writes will succeed.
